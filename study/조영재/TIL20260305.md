### 작업 애로사항
**트러블 슈팅**
1. WSL에서 도커를 사용하는 과정중에 WSL의 도커가 docker.exe를 호출하는 오류가 발생
2. ~/.docker/config.json에서 아래 항목 제거
- "credsStore": "desktop"
3. 그래도 실행이 되지 않는 오류가 지속됨
4. 도커를 재설치함.
5. 도커를 재설치하고 docker compose up을 실행했더니 docker에는 compose up이라는 명령어가 없다는 오류가 발생
6. 이에 따라 docker-compose-v2를 설치함
7. 이후 docker 버전을 확인, docker compose 버전 확인 시 잘 뜨는 것을 확인
8. docker compose up을 실행했을 때도 잘 작동되는 것을 확인함.

**개선사항**
- WSL의 경우에 exe를 사용할 수 없는데, 이때 설정을 공유해서 문제가 되는 경우가 자꾸 생기는 것같음.
- 윈도우와 리눅스의 설정을 분리하거나 멀티 부트를 사용하는 방법을 고려해볼 수 있음
- 2026년 03월 05일 목요일 종례시간에 한기철 컨설턴트님께서 WSL과 멀티부트 ubuntu에 대한 부분을 설명해주셨는데, 확실히 어제 오늘로 WSL 때문에 시간을 많이 소모한 상태라 멀티부트 ubuntu를 사용하는 것이 좋다고 느껴짐
- 만약 WSL을 지속적으로 사용할거라면 위와 같은 트러블 슈팅에 대한 부분을 계속 인지해야겠음
- 만약 ubuntu를 지금이라도 설치한다면 개발환경에 대한 고민없이 개발할 수 있을 것 같음.

**재발 방지 체크리스트**
- WSL 단독 사용 시 ~/.docker/config.json에 credsStore=desktop 유지하지 않기
- docker compose version을 초기 환경 점검 항목에 포함
- 환경 점검 시 아래 4개 명령을 고정 사용:
  - docker version
  - docker info
  - docker compose version
  - docker run --rm hello-world
