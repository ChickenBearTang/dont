### 작업 애로사항
**오늘한 일**
- 인증/토큰 관련해서 refresh token을 쿠키로 바꾸는 작업을 함.
- 여기에 더해서 SID 재사용을 감지하는 로직이나 refresh token rotation을 하는 로직도 추가함
- 전체적으로 기준을 OWASP OAuth 2.0 Protocol Cheat Sheet와 같은 OAuth 2.0 문서를 참고해서 access token은 짧게 refresh token은 길게 하는 방향으로 작업함.

**잘못한 점**
- 기억하기로 이번주 월요일인가 화요일에 우리팀 발표자료에 넣을 시스템 아키텍처 다이어그램을 그리기로 했었는데, auth관련 기능을 제작하다가 까먹는 실수를 했음.
- 다행스럽게도 팀원이 이에 대해서 리마인드 해줬음. 따라서 내일은 시스템 아키텍처를 그리는 작업을 해야할 것 같음.
- 기능을 머지한 후에 이 코드 자체의 컨텍스트가 길다보니까 SPA에서 화면이동시에 refresh token을 매번 재발급 하는 것으로 오해해서 코드를 변경할 뻔함.

**개선 사항**
- 오늘 한 작업 중에서 고민을 한 부분이 refresh token에 락을 적용할지 혹은 lua를 적용해서 별도의 스크립트를 만들어서 refresh token rotation을 할 때마다 refresh token을 새로 발급하는 방법이 있었음. 일단은 락을 적용하는 방법으로 했는데, 이 부분에 대해서는 좀 더 고민이 필요할 것 같음.

**고려할 점**
- 사실 이런 jwt에 대한 부분은 보안적으로 중요한 부분이라서 sonarqube나 PMD같은 정적 분석 도구로 보안 관련한 템플릿을 적용하면 더 쉽게 방어적 코딩을 할 수 있을 것 같음.
- 추가적으로 한기철 컨설턴트님께서 말씀하신 것처럼 파로스와 같은 도구로 취약점을 분석하는 것도 좋은 방법이 될 수 있을 것 같음.
- 프로메테우스나 그라파나와 같은 모니터링 도구를 적용해서 모니터링을 추가하는 것을 고려해봐야함.
